# PR Template

Use this template when creating pull requests with the `publish-open-pr` skill. This packages a finished branch into a reviewable PR.

## Summary

[Brief description of what changed in this PR. Should be understandable to someone familiar with the project but not necessarily this specific work.]

## Why

[Explanation of why these changes were necessary. Connects back to the original issue or spec.]

## Impact

[Description of the impact of these changes. Who or what is affected? What behavior changes?]

## Validation

[Summary of validation performed to ensure these changes work correctly.
- Specific tests that were run
- Manual verification steps
- Any validation that was skipped and explicit justification]

## Review Focus

[Specific areas reviewers should pay particular attention to.
- Areas that are complex or prone to errors
- Recent changes that may need extra scrutiny
- Parts of the code that are particularly sensitive]

## Development

[Brief notes about the development process that might be helpful for reviewers.
- Any particularly challenging aspects
- Decisions made during implementation
- References to related issues or discussions]

[Remember: Use the metadata bundle to set assignee, reviewers, labels, and milestone. Never implement new issue work in this skill; only package, push, and publish the branch that implement already prepared.]
